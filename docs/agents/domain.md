# Domain Docs

This repository uses a single domain-document context.

Before engineering work, read:

- root `CONTEXT.md` for canonical domain vocabulary;
- relevant accepted decisions under `docs/adr/`;
- normative material under `docs/specs/` and `docs/tickets/`.

Use glossary terms as written and avoid synonyms listed in `_Avoid_`. Surface ADR conflicts explicitly rather than silently overriding them.
