# Checkpoint post-submission evaluation results between model calls

Each successful post-submission evaluation responsibility is committed as one Committed Evaluation Result uniquely keyed by Task Attempt, responsibility, and evaluation version before the next evaluation call or learner-state transition begins. Replay and Retry rehydrate the saved submission and these results first: a completed Assessment is not rerun when Rationale Sufficiency Verification is missing or unavailable, a completed verification is not rerun when routing has not yet committed, and only a missing or technically failed responsibility is invoked. The original command replay returns its committed Interaction Boundary, while an explicit Retry resumes the Pending Operation from these checkpoints; Learning Evidence, Learning Stage, and learner-visible interactions remain exactly-once under ADR-0063. An external Provider call may still occur more than once if the process crashes after the Provider returns but before its result commits, because the Provider Catalog has no common transactional idempotency contract; Kiln-AI does not claim exactly-once model invocation across that window.

The durable cutover replaces the append-only `assessments` store with `evaluation_results`, keyed uniquely by `(attempt_id, responsibility, evaluation_version)` and carrying the closed result schema and JSON payload. Response Assessment, Response Verification, Rationale Assessment, Rationale Sufficiency Verification, and Teach-back Assessment use one save-or-return-committed port; concurrent commits use the unique-key winner, and downstream decisions use that committed result. The old table and `recordResponseAssessment`/`assessmentsFor` paths are removed without dual writes or data migration, while Model Contract Audit remains separate. A new `RESUME_SUBMISSION_EVALUATION` Pending Operation carries only the Attempt identity and required responsibility identity; Retry rehydrates the closed Attempt, Task Package, saved submission, and Committed Evaluation Results rather than copying learner input or result JSON into the Pending Operation.
