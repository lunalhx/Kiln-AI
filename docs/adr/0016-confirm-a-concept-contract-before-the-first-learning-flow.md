# Confirm a Concept Contract before the first Learning Flow

Before the first Learning Flow for a selected knowledge-base concept, the Concept Preparation Agent derives source-grounded, versioned preparation artifacts from Normalized Source Documents. Type-specific Gates validate their schemas, source trace, internal references, and declared boundaries before acceptance; a rejected artifact is never silently published. A prerequisite absent from the learner-supplied Target source may be proposed from Target requirements, but it becomes a Required Supporting Concept only after a Gate validates the dependency against approved source authority. Its readiness check and any later Learning Flow require an approved Concept Source Pack from the platform Knowledge Base or another accepted source. If none exists, preparation returns a Source Gap and may tell the learner that the current material omits the prerequisite; it must not generate a test, curriculum, or blocking claim from model memory. The Agent then presents one concise learner-visible Concept Contract containing the Concept name, included and excluded scope, one user-readable Mastery Criterion, and source basis. If the selection is too broad to assess coherently, Kiln-AI proposes smaller Concepts and asks the learner to select one rather than introducing multiple Learning Objectives beneath it.

The learner confirms only that visible Concept Contract. Accepted internal Mastery Rubric, Capability Tags, Supporting Concepts, Diagnostic Plan, subject metadata, and source metadata require no routine learner or expert authoring or approval. The accepted Diagnostic Plan is frozen for one version: runtime selection may adapt only among its declared Target dimensions and Supporting Concepts. It must contain a minimal Target Readiness Set derived from the Mastery Rubric; distinguish Required from merely relevant Supporting Concepts; declare an acyclic prerequisite dependency order; assign prerequisite checks a minimal routing budget; allow version-aligned accepted Concept Progress to satisfy readiness before another task is generated; stop probing at the first sufficient prerequisite recommendation; declare where rationale is useful enough for an optional corroborated-rationale Blueprint; and declare a worst-case count of at most eight Diagnostic Task Attempts across the complete Plan version, including resume. A type-specific Gate rejects a Readiness Set that omits a criterion necessary for safely attempting Independent, expands the Rubric, effectively duplicates a complete mastery exam without justification, enables rationale without a rationale-relevant Rubric mapping, or requires more than eight Attempts. Before Diagnostic starts, its learner projection says that length is adaptive, shows the Plan-specific maximum, and offers Direct Learning; each Diagnostic interaction retains Direct Learning and shows completed Attempts against that maximum without promising an exact remaining count. Resume preserves the consumed count. Reaching the bound applies the accepted neutral termination rules and never silently adds questions. A suspected plan-external prerequisite or Rubric gap returns to the Concept Preparation Agent for a new validated version rather than silently changing the running curriculum; a material change to source basis, Concept boundary, or Mastery Criterion also requires a new learner confirmation. A confirmed Concept otherwise starts or resumes Flows without repeated confirmation. The Concept Contract is a versioned confirmation snapshot, not another progress or evidence entity, and its confirmation does not make the Agent rather than the Source Original authoritative for subject truth.
